# 需求文档

## 简介

本文档规定了OpenHarmony分布式相机系统的macOS构建和测试框架的需求。该框架使开发者能够在macOS上编译、测试和调试分布式相机源代码，而无需OpenHarmony硬件设备。系统通过stub/mock层模拟OpenHarmony系统依赖，同时保持与原始平台的API兼容性。

## 术语表

- **构建系统（Build_System）**: 基于CMake的编译基础设施，将源代码转换为可执行库
- **Source服务（Source_Service）**: 分布式相机控制端服务（SA_ID=4803），管理控制设备上的相机操作
- **Sink服务（Sink_Service）**: 分布式相机被控端服务（SA_ID=4804），提供被控设备上的相机访问
- **Stub层（Stub_Layer）**: macOS平台适配层，提供OpenHarmony系统API的模拟实现
- **外部依赖（External_Dependencies）**: 编译所需的21个OpenHarmony代码仓库集合
- **通道模块（Channel_Module）**: 用于分布式相机数据传输的三通道通信系统（Control/Snapshot/Continuous）
- **数据处理（Data_Process）**: 相机流的编解码和数据处理管道
- **相机客户端（Camera_Client）**: Sink设备上的本地相机访问组件
- **HDF虚拟相机（HDF_Virtual_Camera）**: Source设备上的虚拟相机驱动组件
- **动态库（Dynamic_Library）**: 编译输出文件（libdcamera_source.dylib和libdcamera_sink.dylib）
- **属性测试（Property_Test）**: 在随机生成的输入上验证通用属性的测试
- **单元测试（Unit_Test）**: 验证特定示例和边界情况的测试

## 需求

### 需求1：构建系统配置

**用户故事：** 作为开发者，我希望在macOS上配置构建系统，以便无需手动设置即可编译OpenHarmony分布式相机代码。

#### 验收标准

1. 当开发者运行CMake配置时，构建系统应检测macOS平台并应用适当的编译器标志
2. 当外部依赖缺失时，构建系统应报告哪些代码仓不可用，并继续使用可用组件
3. 构建系统应使用C++17标准和Clang编译器
4. 构建系统应定义平台宏（__APPLE__、__MACOS__、DCAMERA_LOCAL_TEST）用于条件编译
5. 当解析包含路径时，构建系统应按优先级排序：stubs > include > OHOS源码 > external目录

### 需求2：Source服务编译

**用户故事：** 作为开发者，我希望编译Source服务（SA 4803），以便在macOS上测试相机控制端功能。

#### 验收标准

1. 当编译Source服务时，构建系统应生成libdcamera_source.dylib
2. 构建系统应包含base、sourceservice、状态机和common模块的所有必需源文件
3. 当编译OpenHarmony源文件时，构建系统不应修改原始源代码
4. 构建系统应链接cJSON静态库和C++标准库
5. 当编译完成时，动态库应导出OpenHarmony接口中定义的所有公共API符号

### 需求3：Sink服务编译

**用户故事：** 作为开发者，我希望编译Sink服务（SA 4804），以便在macOS上测试相机提供端功能。

#### 验收标准

1. 当编译Sink服务时，构建系统应生成libdcamera_sink.dylib
2. 构建系统应包含sink服务入口点和所需依赖
3. 动态库应可独立加载，不依赖Source服务
4. 当编译完成时，动态库应导出sink操作的所有公共API符号

### 需求4：OpenHarmony系统API模拟

**用户故事：** 作为开发者，我希望在macOS上模拟OpenHarmony系统API，以便代码可以在没有OpenHarmony运行时依赖的情况下编译和运行。

#### 验收标准

1. 当调用OpenHarmony系统API时，Stub层应提供返回成功（0）的模拟实现用于仿真
2. Stub层应保持与OpenHarmony接口的API签名兼容性
3. 当包含stub头文件时，构建系统应优先使用stub实现而非OpenHarmony系统API头文件
4. Stub层应模拟HiLog、IPC、系统能力管理器和设备管理器API
5. 当调用模拟函数时，Stub层应记录调用以便调试

### 需求5：外部依赖管理

**用户故事：** 作为开发者，我希望正确集成外部OpenHarmony依赖，以便分布式相机代码可以访问所需的类型和接口。

#### 验收标准

1. 构建系统应从external目录引用21个OpenHarmony代码仓库
2. 当外部代码仓存在时，构建系统应包含c_utils、IPC、hilog、safwk和distributed_hardware_fwk的头文件
3. 当外部代码仓缺失时，构建系统应发出警告但继续使用可用组件编译
4. 构建系统不应修改外部代码仓内的文件
5. 当发生头文件冲突时，构建系统应优先使用外部代码仓的头文件而非stub头文件进行类型定义

### 需求6：通道模块集成

**用户故事：** 作为开发者，我希望编译三通道通信系统，以便测试Control、Snapshot和Continuous数据通道。

#### 验收标准

1. 构建系统应包含services/channel目录的通道模块源文件
2. 当编译通道接口时，构建系统应包含icamera_channel_listener.h及相关头文件
3. 构建系统应编译协作管理器CAPI接口用于全连接场景
4. 当通道代码引用softbus API时，Stub层应提供模拟实现

### 需求7：数据处理管道编译

**用户故事：** 作为开发者，我希望编译数据处理管道，以便测试编码、解码和流处理功能。

#### 验收标准

1. 构建系统应包含services/data_process目录的数据处理源文件
2. 当编译数据处理模块时，构建系统应包含pipeline、interfaces和utils头文件
3. 构建系统应编译流数据处理和feeding smoother组件
4. 当引用编解码API时，Stub层应为av_codec接口提供模拟实现

### 需求8：构建产物管理

**用户故事：** 作为开发者，我希望构建产物有组织且可安装，以便轻松部署和测试库。

#### 验收标准

1. 当编译成功时，构建系统应将动态库放置在构建输出目录
2. 构建系统应提供install目标，将库复制到标准位置
3. 当安装库时，构建系统应保留库依赖和链接信息
4. 构建系统应生成调试符号以支持调试
5. 当执行清理操作时，构建系统应删除所有生成的产物而不影响源代码

### 需求9：错误处理和诊断

**用户故事：** 作为开发者，我希望在编译期间获得清晰的错误消息，以便快速识别和修复构建问题。

#### 验收标准

1. 当源文件缺失时，构建系统应报告具体文件路径并继续使用可用文件
2. 当找不到头文件时，构建系统应报告缺失的头文件和包含它的文件
3. 当链接失败时，构建系统应报告未定义的符号并建议可能缺失的stub实现
4. 构建系统应显示配置状态摘要，显示找到和缺失的依赖
5. 当出现编译警告时，构建系统应显示警告但不将其视为错误

### 需求10：API兼容性验证

**用户故事：** 作为开发者，我希望验证与OpenHarmony的API兼容性，以便在macOS上测试的代码能在目标平台上工作。

#### 验收标准

1. 当创建stub实现时，Stub层应完全匹配OpenHarmony API签名
2. 如果stub签名与OpenHarmony头文件不匹配，构建系统应编译失败
3. 当添加新的OpenHarmony API时，构建系统应报告缺失的stub实现
4. 构建系统应验证动态库中的所有导出符号与OpenHarmony接口规范匹配
5. 当运行API兼容性测试时，构建系统应验证函数签名、参数类型和返回类型

### 需求11：增量构建支持

**用户故事：** 作为开发者，我希望增量构建正确工作，以便在开发过程中快速迭代。

#### 验收标准

1. 当修改源文件时，构建系统应仅重新编译受影响的文件及其依赖项
2. 当修改头文件时，构建系统应重新编译所有包含它们的文件
3. 当修改stub实现时，构建系统应重新编译和重新链接受影响的库
4. 构建系统应准确跟踪依赖关系以避免不必要的重新编译
5. 当未检测到更改时，构建系统应跳过编译并报告目标是最新的

### 需求12：调试和发布构建模式

**用户故事：** 作为开发者，我希望以调试或发布模式构建，以便针对调试或性能进行优化。

#### 验收标准

1. 当选择调试模式时，构建系统应使用-g -O0标志编译并启用所有调试符号
2. 当选择发布模式时，构建系统应使用-O2 -DNDEBUG标志编译并优化性能
3. 构建系统应允许在调试和发布模式之间切换而无需完全重建
4. 当调试模式激活时，构建系统应启用额外的运行时检查和断言
5. 当发布模式激活时，构建系统应剥离不必要的符号以减小库大小

### 需求13：文档和示例

**用户故事：** 作为开发者，我希望有文档和示例，以便了解如何使用构建系统。

#### 验收标准

1. 构建系统应提供记录构建先决条件和设置步骤的README
2. 构建系统应记录stub层架构以及如何添加新的模拟实现
3. 构建系统应为常见构建错误提供故障排除指南
4. 构建系统应记录外部依赖的获取和配置方法
5. 构建系统应提供构建命令的快速入门指南
